# 分层架构

## B 站点播清晰度策略

`shared/bilibili-quality` 定义分辨率上限、自动/记忆策略及旧配置迁移；1080P80、高码率112、60帧116保留独立身份，但按同分辨率分组。`BilibiliQualitySettings` 只呈现「观看」页控件，经现有Preferences/IPC及桌面、安卓原子存储保存，不直接请求来源。

共用 `PlaybackSessions.resolve` 从已保存偏好计算初始请求，并在DASH构建前过滤超上限候选，返回菜单仅来自实际可播放轨道；MP4响应超限或无法确认画质时拒绝。缺少记忆档时取不高于目标的最高分辨率，同分辨率保留服务端顺序，若全在其上则取上限内最低分辨率，候选为空报错；账号权限、DRM和编码检查保持。直播、本地与直链不应用该策略。

`usePlayback` 在新打开、手动切集和自动续集时不携带上一集回退后的清晰度，明确切画质和失败重试仍携带目标并受上限约束。`chooseQuality` 只在请求成功、未取消时，通过现有偏好写入通道记录具体手动选择；即使服务端临时回退也记录用户所选档位，自动回退不改写记忆，确认当前画质不重载。`usePreferences.settled` 在B站点播解析前等待已排队写入，播放随后再次核对取消代次，不阻塞本地、直链或直播；保存失败沿原通道反馈/回滚。设置改变不主动中断当前视频，菜单即时排除超限项，后续解析应用新策略。

## 跨内核玻璃与按钮

玻璃效果按CSS实际能力分级，视觉注册和按钮光照不读取业务状态或媒体帧。旧WebView仅对弹窗后的已停用浏览外壳使用普通模糊，播放页面始终不滤镜化视频；两端按钮共用薄填色/边缘及有界确认反馈，菜单组内不叠加独立背景滤镜。播放器提示底色贴合文字，原两行容量和命中坐标保持。模块职责、苹果官方设计依据及验收边界见 [玻璃材质与按钮](glass-materials.md)。

## 安卓播放与搜索的兼容边界

`dash-video` 保持先选清晰度、再选该清晰度编码的顺序。安卓后端注入 `androidVideoSupport`，以当前 WebView 的 `MediaSource.isTypeSupported` 和原生 `VideoSupport` 有限格式能力查询共同评分；仅正面确认的 HEVC 可扩展候选，能力不足不跨清晰度降级。原生桥只接收编码、尺寸、帧率，不接收媒体 URL 或凭证；两层独立查询，有界缓存仅保存能力元组，选轨仍要求交集。播放来源携带所选清晰度至多三类有限能力，MEDIA3/4由纯共享格式化函数转换为系统声明及内核支持反馈；实际选中编码对应精确轨道，其他编码对应最佳候选。能力声明不等于实际解码成功，未知不能误报为确定不支持。能力依据为 [Android CodecCapabilities](https://developer.android.com/reference/android/media/MediaCodecInfo.CodecCapabilities#isFormatSupported(android.media.MediaFormat))。

`Player` 按 `sessionId` 重建 video 与弹幕层；媒体 hook 捕获原元素负责旧引擎和进度的清理，新元素隔离迟到媒体事件，弹幕尺寸监听也跟随新元素重建。同会话详情补全仍不重建媒体。弹幕合成动画继续逐显示帧运行，主线程每50ms维护条目、每0.5媒体秒读取漂移；媒体状态事件立即锚定，释放时移除监听。

`bilibili-list-response` 仅验证搜索与影视索引的数据列表。code=0但返回验证凭据、缺失列表或首屏空列表与非零总数矛盾时保留失败，不把异常缓存成空结果；显式零结果及正常服务端顺序保持。该校验不能证明实体电视真实空响应的原因，也不改变授权或推荐。

## 安卓电视适配

`danmaku-lanes` 利用排布器对同一方向滚动文字使用统一速度的性质，将同排布行合并到一个动画容器，子span只设置静态位置。透明度作用于各行或固定文字，父弹幕区域不再执行整屏透明度合成。`media-translation` 统一装饰节点的媒体时钟同步，单条回退与共享行均不操作视频。每8媒体秒重设坐标，避免长时间播放累积巨大光栅坐标；行内最后文字离开时释放动画，布局/来源变化释放全部行。合并不减少弹幕数量或改变排布，固定/反向模式继续保留。

`src/android/frontend.ts` 在启动前挂载相同的命名 `HubApi`，通过原生 `HubBridge` 调用隔离后端 WebView。`android/backend/entry.ts` 复用现有 BilibiliProvider、BilibiliAccount、PlaybackSessions 与 IPC Zod 模式；构建时仅替换存储、网关及 Node 平台依赖，不复制修改推荐实现。

Java 的 `MainActivity` 派发七键语义事件与暂停事件；`AppWebClient` 只服务打包本机来源并禁止外部页面导航，UI 不持有后端桥。后端使用 `BackendBridge` 调用原生受限 HTTP、Keystore、原子存储、SAF 本地授权及媒体网关。媒体以不可猜测的会话资源注册并释放，Range 流不发送平台 Cookie；账号 Cookie 仅允许准确受信 HTTPS API 主机。UI 与后端均禁止文件 URL、弹窗、下载和页面权限，正常 APK 不开启调试。

`StartupFailure` 独立提供不依赖 WebView 的原生启动错误页，读取实际 Android/API 及 WebView 版本，明确区分过旧/不可用组件和初始化阶段错误。纯文本不占焦点，重试/退出由原生按键处理；初始化失败销毁部分创建的 WebView，防止隐藏视图继续消费按键。错误页不显示原始异常消息或账号数据。

Android 构建将前后端语法降至 Chromium66。`runtime-compatibility` 补齐实际使用的标准 API 及安全随机 UUID，`dom-compatibility` 提供 inert/ResizeObserver/replaceChildren；字素删除缺少 Intl.Segmenter 时使用 Graphemer。旧内核焦点与布局样式仅在能力检查失败时启用，构建插件转换 inset、grid-gap、appearance 等等价声明。MP4 初始化段的64位长度按两个32位字检查，在64KiB边界下拒绝非零高字，不依赖 BigInt、不放宽加密检查。Zod 的未使用64位常量在 Android 构建中经 JSBI 精确初始化，原 JSON IPC 校验不变。Android 视频使用内嵌透明封面，避免旧 WebView 默认封面被 CSP 拒绝而触发错误，未放开外部协议或页面权限。

遥控器与键盘/手柄共用 `use-input` 的活动范围、焦点、滚动、确认和返回；`remote.ts` 只校验七键与提供对应提示。浏览菜单动作在 App 层接线到详情/设置，播放菜单动作在现有 Player actions 中揭示播放设置；不创建第二套播放生命周期。Android 与桌面共用同一界面和字号模式，设置/顶栏不按平台隐藏入口，原生始终横屏全屏，播放器窗口全屏按钮在同位置禁用。第三方网页自动检测尚未移植，链接解析明确失败，不创建伪造来源。

## 桌面与共用模块

Android 的 `HttpBody` 只协商并解压 gzip、raw/zlib DEFLATE，解压后仍由原受限读取器执行4MiB或初始化段上限；响应去掉已失效的编码和压缩长度，HEAD/无正文状态不解压。`dash-range` 通过 DASH 引擎请求拦截器只把已注册本机媒体的 Range 转成本机参数，原生网关校验并向原资源发送同一 Range，参数不进入上游地址；避免旧 WebView 对已切片流再次执行 seek。`SizedStream` 为旧内核报告实际已知长度并维护剩余读取数，原生连接在流关闭或会话释放时撤销。设计依据见 [DASH 拦截器](https://dashif.org/dash.js/pages/usage/network-interceptor.html)及[旧 WebView 对响应流执行 Range seek 的源码](https://chromium.googlesource.com/chromium/src/+/56a49354fb9b5735e8e1eb78e786e23f4c080d55/android_webview/browser/net/android_stream_reader_url_request_job.cc)。桌面、推荐、平台权限和播放顺序不变。

Android 的 `HttpFailure` 将原生网络异常转换为有限 DNS、TLS、超时或连接失败类别，桥不传原始异常消息/地址；`ConnectionFailure` 提供通用反馈，BiliHttp 仅针对 B 站转换就地文案，不改变请求合同。`abort-signals` 在旧内核不能保留 abort reason 时内部记录超时身份，组合信号保留首个原因并清理监听；主动取消仍为 AbortError。系统信任库、TLS/主机名校验保持。屏幕键盘候选使用拼音整行、五列候选及独立翻页列，避免 Chromium66 flex 收缩到10px。

`AppShell` 将主导航和工具区置于顶部，`TopNavigation` 只呈现横向栏目及设置入口。`browse-hierarchy` 将主导航、设置、搜索和账号合为完整顶栏，按显式 `data-browse-nav` 识别子栏与筛选；未滚到顶的上键限定在内容中。`browse-navigation-actions` 管理 B 逐级返回最近父栏，以及 LB/RB 最近层遍历、边界升层；顶栏工具只落焦，确认才执行。页面与列表状态保留，模态/播放/解析取消的返回优先级保持。

`input/layout-navigation` 在通用几何选择之前消费布局内的方向移动：顶栏和播放器按钮左右沿本行，媒体卡片左右按同网格顺序跨行且首尾停止；播放器按钮上键进入进度条，设置上下遍历当前可聚焦设置行。因此宽进度条或偏左滑条不会因控件中心距离而抢占/丢失预期焦点。候选仍由活动范围、禁用和 inert 规则统一筛选，不读取媒体、请求来源或修改偏好。

## 前端结构

手机遥控顶栏复用navigation六个栏目，二级分类来自共用browse-sections；横向滚动保留固定搜索/历史/工具按钮，无底栏。PhoneSearch在居中卡片编辑，PhoneBrowse独立请求筛选和分页，companion-dynamics仅传完整动态显示字段及独立配图句柄。usePhoneView管理开始播放自动进入、首页气泡、两页滚动恢复与导航代次；切集不打断已最小化页面，迟到播放不覆盖新卡片。PhoneSheet原生dialog按visualViewport居中及限制高度，返回回工具、关闭恢复原入口。PhoneHistory区分已有网页授权的B站历史和重新读取的本机记录，后者不提交App初始化状态，句柄保留具体分集。目录/收藏夹/相关推荐读取在手机端串行，不排队或重放写入。PhoneSettings按观看/弹幕/界面挂载当前组并发送偏好补丁。RemoteButtons保留方向/滑动及六个快捷键，ControlButton松手提交、静止长按连发，取消手势不补发兼容click。

`input/setting-editing` 只管理设置select/range的编辑意图：确认进入编辑后左右才调用原adjustSelect/adjustRange，上下/返回/完成结束编辑；原即时偏好回写与失败回滚不变。滚轮转交所在模态滚动，滑条首次短点只进入编辑，首次滑动不写入。该门控不作用于播放器时间线和参数菜单。顶栏移除独立键盘按钮，单一搜索框确认进入屏幕键盘，原生空搜索回车也可打开，非空回车仍提交搜索。

usePhoneController接收命名原生桥指令，按键交给useInput，显示数据与直接操作交给useCompanion。companion-catalog注册有界、账号隔离的不透明句柄，只返回标题/作者/时长/来源与封面能力，不返回路径、URL或平台身份。封面经既有受限图片通道读取，限制体积后作为data图片返回。player-companion通过现有media/transition控制播放，检查会话、覆盖层与操作代次，保持暂停、位置及取消释放；切片/画质/重试返回实际解析结果。PlayerVideo只装配原媒体事件，仍按session重建。偏好经usePreferences串行保存并返回成功布尔值。浏览与搜索沿用原Provider，不改变电视路由；related单独读取普通视频下的相关推荐，不进入首页推荐会话或自动连播队列。前端轻量校验与仅后端使用的Zod模式分离，避免旧WebView前端新增BigInt依赖。

桌面electron/remote及安卓原生PhoneController/ControllerHttp随应用自动监听内网IPv4随机端口。二维码片段含随机256位会话密钥，页面读取后移出地址栏并按浏览器同源本地保存，支持新标签页重访；401和主动忘记清除，应用重启更换密钥。命令仅通过Authorization请求头提交。服务仍只允许静态路径、状态和有限命令，校验内网对端、Host/Origin、参数及大小/时限/并发；结果按白名单模式过滤，不开放通用IPC、任意文件或媒体代理。暂停取消等待操作但保留监听，后台拒绝指令，退出关闭服务；断线不重放操作。网页预览不伪造原生服务或账号能力。

设置由 `Settings` 按观看、弹幕、手机遥控、手柄分类挂载当前面板，观看控件集中于 `ViewingSettings`。分类使用手动确认的tab语义，`settings-navigation` 只决定分类左右及首控件上下落焦；`setting-editing` 保持先确认后编辑，保存仍通过原偏好串行模块。两端相同字号/视口下使用同一DOM、CSS与控件尺寸，旧WebView仅做能力回退，不另建电视设置页。

通用 URL 播放通过已有 `openUrl/resolve` 进入主进程。`url-media` 提供纯地址与格式契约；`web-media-probe` 在无 preload、无 Node、独立临时会话的隐藏静音窗口内有界检测，`web-media-script` 读取各 frame 的 video、元数据、已配置地址和媒体资源，对可见原生视频触发静音播放，并触发已知播放器的播放按钮。`web-media-request` 保留对应页面 Cookie、必要 Referer 和 User-Agent，按 Chromium 请求身份跟踪至多五次受限 HTTP(S) 重定向，补全 Electron 未提供的最终响应地址；内部关联标记发送前移除，不读取平台凭证。返回经白名单 `cancelUrlResolution` 中断等待并销毁窗口；应用退出也取消，成功后临时会话由 PlaybackSessions 持有，释放时清理存储与缓存。历史保持原页面身份，媒体通道地址不持久化。

`read-manifest` 按流限制清单大小及读取时间。`web-dash` 展开 BaseURL 与继承的分段定义，保留音视频轨、时间线和 byte range，重写 SegmentList/Template/Base；`url-template` 仅为已注册媒体允许有限数字参数。XML 外部实体、外部链接和明确 ContentProtection 被拒绝。HLS 子清单、分段、初始化及普通密钥 URI 继续经会话能力转发；媒体网关不转发渲染器 Cookie。网页 DASH 使用自适应选轨，B 站单画质合同保持。检测到地址与真实媒体解码分别验收，网页登录、验证码及 DRM 不提供绕过。

`usePlayback` 在打开时记录 App 弹窗代次，解析成功仅关闭同一发起弹窗；播放中迟到切集/切画质结果不关闭后来打开/重开的设置，未知分集读取阶段同样保持。原请求代次及退出取消仍隔离过时播放来源，不重排队列或推荐。

`UrlForm` 独立呈现链接输入及就地错误，通过 AppDialogs/App 给 usePlayback 注入仅本次打开的失败回调；其他入口沿用 notify。表单同步门控重复确认，等待只读原地址并保留输入/确认焦点，IME Guard 阻止输入法确认误提交。错误保留到修改地址或组件退出，重试等待不撤下原原因；失败回调核对组件活动与操作代次，不更新已关闭或重开的表单。来源解析、账号及会话仍由原能力负责。

网页检测每轮提交新页面快照给纯函数 `web-media-selection`，与持续收集的网络候选合并：当前可见视频按面积优先，未知的元数据/网络发现其次，已知隐藏或零面积资源最后。同地址兼容 MIME 与当前 frame Referer，保留 blob/MSE 网络发现和无扩展名媒体。CSS 隐藏/透明视频不主动 play，仅隐藏候选不提前结束等待，期限末仍可回退。页面快照替换旧可见性，避免布局变化后保留旧大播放器优先级；不向渲染器暴露网页凭证、不修改 B 站解析，不声称已自动识别任意网页广告意图。

`web-media-availability` 仅消费同一临时会话已有响应，按 Chromium 请求身份将重定向404/410关联到原始、中间和最终地址；候选选择排除当前已确认缺失的资源，后续非缺失响应解除排除。HTTP身份忽略片段、保留查询，缺失与重定向记录均有界且释放清除。`web-media-request` 通过可选的内部重定向观察回调接线，受限重定向、最终地址与标记剥除保持原职责。检测不额外发HEAD/GET，不消耗另一份临时资源；所有候选失效时沿用 UrlForm 失败回调就地反馈并保持地址/焦点，不将HTTP状态当作格式解码或权限成功。

`input/focus.css` 的通用 modal 提示区为两行常用操作预留高度，隐藏模式保留提示原占用空间而只隐藏文字，初始空宿主也保持基准高度。这样手柄/键盘/鼠标切换不令居中弹窗移动，固定坐标点击仍落到原控件；后台提示仍受活动范围约束，播放器自己的提示规则保持。模态底部滚动安全区与提示可见性解耦。

焦点描边由 `input/focus.css` 和主题 `--focus` 统一管理，使用2像素中性色单层描边及3像素外距；浅色深灰、深色近白，播放器固定近白，不叠加绿色光晕。顶栏搜索仅保留输入框一个焦点，由搜索外壳呈现唯一描边，确认进入屏幕键盘；描边不占布局空间，不改变已选状态或空间导航。aria-disabled/data-focus-retain 控件在实际键盘或手柄焦点上不整体淡化，保留细描边对比度；忙碌/成员状态、确认门控和无效动作提示仍由原业务和input规则决定。

选集及倍速/清晰度侧面板通过 `player-menu-hints.css` 独立共享提示占位，按当前桌面/电视的实际提示字号预留两行及原选集间距。空宿主、提示隐藏及输入模式切换保持菜单、滚动视口和选项几何位置，只隐藏提示文字；活动范围和语义仍由 input/hints 管理，不复制确认/返回逻辑，也不改变通用 modal 或播放器底部布局。

`App.tsx` 负责状态与流程接线，`navigation.ts` 统一路由与栏目定义。`useBrowseFeed` 管理列表缓存、分页与原有推荐预取合同，`usePlayback` 管理播放打开、取消、分集续播和返回焦点。`AppShell` 呈现导航、搜索、页面标题与快捷键；`BrowseContent` 组合各栏目，`HomeContent` 优先展示继续观看与推荐。`FeedResults` 区分授权缺失、加载、错误和空状态，`MediaGrid` 统一视频列表，`QueueList` 与 `AppDialogs` 分别装配队列及弹窗。展示组件通过回调调用上层能力，不自行实现平台请求或播放会话调度。

`useBootstrap` 区分初始化失败与来源状态；`usePreferences` 即时更新界面、串行持久化并回滚失败写入；`useQueueActions` 管理写入与忙碌状态。`useMediaDetails` 与 `useAccountLogin` 承担异步操作及过期请求隔离，呈现组件通过回调使用能力。`Player` 接线媒体、窗口与语义输入，`usePlayerMedia` 管理引擎、进度与释放，`usePlayerWindow` 管理全屏恢复；`PlayerControls`、`PlayerFeedback` 和 `EpisodePicker` 分别呈现控制层、状态与选集。

`useBootstrap` 合并同一轮请求并保护期间的编辑，刷新失败不隐藏已有内容；`useFavoriteFolders` 独立处理收藏夹列表、账号变化、空数据和失败重试。`DetailsSummary` 呈现紧凑封面与可滚动全文标题，详情主操作粘附在弹窗标题下方，选集优先于简介。`PlaybackSettings` 与 `DanmakuSettings` 分别呈现播放策略与默认速度、视频弹幕选项；设置继续即时串行保存，旧偏好补充默认字段，不重置既有连播选择。偏好模块提供 change/isPending，App 将只读等待状态接入初始化保护：读取开始时有排队设置即保留当前值，提交时也再次核对，防止播放返回或迟到快照覆盖新选择；空闲权威读取仍应用并更新下次失败的回滚基准。等待状态包含串行的全屏阶段，不阻塞播放返回，也不将窗口能力与初始化直接耦合。

`useDanmaku` 通过显式会话接口读取弹幕并隔离迟到结果，`DanmakuLayer` 管理实际画面尺寸，`visual/danmaku-renderer` 复用当前 span，不逐帧提交React。`danmaku-window` 二分定位当前时间附近，只预排15秒未来内容及有界回看窗口，每帧最多80条/约2ms，跳转不处理经过的整段电影。`danmaku-motion` 使用合成线程线性滚动，并以媒体时钟校准漂移、暂停/缓冲、倍速和跳转；无动画能力时直接按媒体时间定位。`shared/danmaku-layout` 继续管理车道及碰撞。卸载或布局变化取消动画并移除节点，不创建可交互内容或执行弹幕文本。

新关键词及从其他栏目提交搜索复位到全部媒体类别，同关键词重复提交保留当前筛选与缓存。搜索类别仍独立请求、缓存、分页及按服务端顺序合并，不改推荐合同。

安卓DASH注册媒体时保留平台同轨备用地址，仅原生网关可读取。`RemoteMediaConnection` 在连接/404/410/5xx失败后按原顺序尝试最多四个备用地址；`ResumingMediaStream` 在已开始响应断流后按精确未读字节请求并核对206、范围、总长度和类型，复用原响应身份及画质。权限失败不回退，用户直链不接受该能力，不发送Cookie，释放清理连接并阻止迟到备用请求。

`PlayerHeading` 独立呈现标题与分集来源，纯展示内容不参与焦点导航；详情标题完整换行，简介及动态正文保留真正需要的滚动入口。应用 Logo 同样只展示品牌。进度预览与操作按钮继续使用现有语义和控制层隐藏规则，弹幕开关呈现可见选中态。当前布局与新增验收针对正常桌面和电视全屏。

控制层状态由 `usePlayerOverlay` 管理，显式隐藏与五秒自动隐藏使用同一状态路径。`PlayerOptionPicker` 是倍速/清晰度的独立模态界面，按钮入口避免原生选择框吞掉方向导航，打开后后台控制层 inert；确认通过父层回调应用，取消不改变参数，卸载恢复入口。`player-actions` 按菜单、跳转、可见控制层、退出依次处理返回，并隔离菜单中的媒体快捷键。切画质的入口保持意图与媒体/分集绑定，避免快速初始化默认焦点覆盖菜单返回；同一意图保存操作前的暂停状态，平台返回不同实际画质时仍有效，其他切换先清除旧意图。`usePlayerMedia` 的准备回调初始化播放意图，`setPlaying` 更新最后一次暂停/继续，`isPaused` 在加载前查询意图、就绪后查询实际媒体状态。媒体元素与 DASH 引擎关闭隐式自动播放，元数据恢复精确位置和最新速度/输出参数后才按当前意图显式启动，避免旧闭包覆盖加载期间的操作。休眠、退出与切换先撤销播放意图；播放 Promise 拒绝核对所属会话和操作版本，仅当前失败更新反馈，主动暂停或旧会话的拒绝不会污染当前界面。首次打开、切集及队列保持默认自动播放，默认速度仅初始化新播放器。选集和参数组件显式导入共享 player-menu-scroll.css，用一致的内边距和滚动安全区容纳外描边，包含深列表定位及首末项；不改菜单选择、焦点恢复或来源顺序。

`DynamicFeed` 的视频项使用共用 `media-grid` 列数，视频外层去掉额外内边距与重复焦点，封面尺寸与首页一致；作者、时间、完整正文、图文和转发保留。长视频正文可聚焦滚动，电视模式不再将动态视频强制为整行。

`bilibili-dynamic-live` 校验 `major.live_rcmd.content` 内嵌的 `live_play_info` 及房间 ID，复用 `normalizeLive` 和既有卡片呈现封面/标题/状态；转发保留同一身份。字段依据见[动态接口记录](https://gitea.s1f.ren/shiran/bilibili-API-collect/blame/commit/cb4f767d4ee3f4f66b6caff04c9c40164ea4af54/docs/dynamic/all.md)。异常通知不使整页失败，视频筛选仍排除直播通知。

普通视频 `playbackDetail` 将最新详情与 WBI 键读取重叠，`PlaybackSessions` 仍先从新详情匹配分集，再签名请求播放地址；详情失败优先传播，键失败不能发送未签名请求。影视/直播、默认画质、权限和取消后的迟到会话释放不变。`shared/media-failure` 只显示有限 MEDIA/DASH 码/类别，不能把引擎原消息或播放地址输出到产品；Android bootstrap 版本由 manifest 构建注入，与 APK 一致。

`shared/dash-settings` 保留来源自动/手动选轨策略，仅安卓将长视频最高画质预取限制30秒、已播保留10秒；当前dashjs默认分别为60秒/20秒，长视频阈值600秒。桌面保持默认。缓存收紧降低媒体缓冲压力，不能替代实体设备内存/硬件解码诊断或证明错误根因。

通用 `Modal` 保留固定标题和底部操作提示，滚动顶部安全区在电视模式扩大以容纳实际外描边；详情固定操作区的独立留白仍优先。播放设置和长队列复用这一规则，不新增滚动或焦点状态。

通用弹窗、参数、选集及收藏夹子面板通过 `focus-return.scheduleFocusReturn` 在后台解除 inert 后执行入口恢复，保存打开前的活动范围；等待期间的新语义、键盘或指针操作取消恢复。收藏夹在原父范围恢复收藏入口，重开面板和父弹窗关闭不会被旧回调覆盖。回调不进入新范围，也不唤出隐藏播放器，正常关闭及稳定相邻入口规则保持；短期监听在执行或取消时释放。

`CoverImage` 使用 shared/images 的纯展示缩略图规则，封面/详情 960px、头像 160px、动态配图 1440px，保留原比例和已有 CSS 裁切。只有受信 B 站静态无查询图片转换，动画、签名查询和外部来源保留；替换已存在的 CDN 加工后缀，不更改平台适配、缓存或持久化的原始字段。桌面图片继续由原受限无凭证协议请求，浏览器预览使用相同目标地址；异步解码不改变失败状态或内容身份。

`browse-page` 以当前主内容视口和可聚焦卡片几何位置按屏选目标，兼顾所在列并同步滚动；越过首行时落到对应顶部筛选/刷新。App 仅在无覆盖层/播放的浏览范围将 rewind/forward 路由到该模块，其他范围保持既有语义。模块不持有来源缓存、加载游标或分页状态，滚动继续由原列表机制处理；提示读取当前映射和主内容可滚动状态。

`DynamicFeed` 的非视频外层卡片使用现有 `data-scroll-content` 阅读语义，完整图文/转发内容在有限高度内滚动。`scrollContent` 到边界返回未消费，空间导航即可移出；LT/RT 由浏览语义优先消费，不落入卡片阅读。CSS 留出嵌套视频焦点边框所需滚动安全区，来源字段、筛选、分页和视频尺寸合同保持。

`usePlayback` 首次播放前将明确浏览入口交给 `rememberFocusReturn`，取消/退出经 `scheduleFocusReturn(document, ...)` 等待浏览范围恢复并核对播放代次。快照记录原入口、所属卡片与同列表相邻项，存活节点优先、稳定 `data-focus-key` 兼容重建，入口消失后优先后项再前项；播放返回用最近滚动保证可见。恢复排队时释放 hook 中的快照，避免长期保留旧列表节点；不再向 hook 注入主内容 DOM。新的语义动作、键盘、指针或覆盖层会取消旧返回，晚到来源仍按原生命周期释放；不把焦点恢复与媒体解析或进度保存绑定。队列播放按钮的身份使用独立 `queue:` 命名空间，不与网格或分集混淆。

`use-input` 切回手柄模式先更新当前提示，再对活动浏览范围的同一主内容焦点执行最近滚动，适应底部提示出现造成的视口缩小；不重新选择条目，也不介入播放器、覆盖层或手柄排除控件。焦点恢复按节点集合和稳定身份索引查找，避免对深列表重复扫描每个候选。

原生 video 错误与 HLS/DASH/FLV 失败回调统一进入 `usePlayerMedia.fail`，先锁定当前会话失败、撤销播放并暂停/保存，再呈现反馈。失败状态仅随新会话重置，元数据不再启动失败媒体；`playing` 事件必须符合当前会话和最新播放意图，错误后的 ended 不触发连播。自动播放的 NotAllowedError 保留暂停及显式继续，其他实际失败显示中文反馈。`Player` 收起参数/选集与跳转预览，错误界面的重试重新解析原身份和位置；清晰度失败的旧恢复不能通过媒体接口播放已失败会话。非致命 HLS 回调与正常媒体顺序保持。

`usePlayerTransition` 独立串行协调切集、画质和重试，操作代次约束保存后的动作、错误反馈、忙碌结束与失败恢复。质量返回意图由模块持有并按媒体/分集一次消费，不泄露媒体引擎状态。取消时递增代次、清除意图并取消上层解析，新操作立即可用；旧操作的 finally 不得影响新操作。失败后的绘制帧恢复另外核对媒体模块只读提供的 playbackRevision；等待解除后新确认的暂停/继续会更新版本，旧恢复不覆盖新操作或重复调用播放。该接口不泄露引擎及凭证。队列入口在等待保存前记录代次、会话与覆盖层版本，切换、休眠、退出或覆盖层开关后不再打开；覆盖层版本在布局阶段递增，关闭新菜单后也不恢复旧请求。`usePlayback` 订阅休眠并取消首次/后续解析，首次准备取消恢复入口；`usePlayerMedia` 收到同一事件先通知切换协调取消，再撤销播放意图并暂停/保存，保留当前视频和控制层。真正的来源释放仍由已有会话层负责，推荐及分集/队列顺序保持。

本机片库由 `useLibraryActions` 独立管理导入/扫描忙碌状态、取消结果和原操作重试，不复用播放打开状态。`LocalContent` 保留既有列表，`LibraryFeedback` 只提供当前操作必要状态。导入的视图版本与路由、播放器及弹窗绑定，完成时只在原视图仍当前时导航，跨视图结果仅更新已提交数据。主进程注入原生选择器到 `storage/local-library.ts`，统一阻止并发选择/扫描，经 `Store.update` 提交获授权根路径及去重媒体。`LocalImportResult` 明确取消、实际发现数与新增数；IPC 参数和命名白名单保持原样，返回数据使用更新后的共享契约，未增加渲染器磁盘能力。

`LibraryButton` 统一文件/目录导入、扫描和重试的呈现门控：忙碌使用 aria-disabled/data-focus-retain 保留入口，点击不提交；`library-button.css` 只淡化内部标签，保持外部焦点描边对比度。播放准备仍按原生禁用处理，业务单请求锁仍在 `useLibraryActions`。已提交片库为空时邀请入口保持，不因等待/失败移除；失败状态由独立反馈明确显示，相同操作重试保留原错误/按钮，确认成功后清除，取消不产生成功状态。新操作可清除旧错误；呈现模块不调用文件选择或存储，主动切页/移动后的焦点不由晚到结果恢复。

`hooks/player-exit` 通过显式回调启动退出、撤销播放意图并显示返回反馈，等待已有进度保存及窗口恢复后关闭。`usePlayerTransition` 的同步退出标记阻止重复动作，响应式 `exiting` 让控件保留焦点和忙碌状态；语义动作在退出时全部消费，原生点击处理也检查同步标记，上一集/从头播放不再能重置待保存位置。迟到错误和播完事件保留退出反馈，提示不显示无效操作。焦点回调核对退出前的原活动范围，旧帧不进入新播放器或弹窗。正常 B 的菜单/跳转/隐藏/退出层级保持，保存失败及来源释放继续交由原媒体和会话模块处理。

缓冲恢复监听归属 `usePlayerMedia` 的来源生命周期。原生 `canplay` 仅在元数据已归属当前会话、媒体未失败且具备后续可播放数据时更新加载呈现，不调用播放接口。这样缓冲后暂停仍能显示已暂停和继续入口，参数菜单保留焦点；加载前的过早事件、旧来源和失败会话不误报成功。卸载/切换与原元数据监听一同清理，不另建缓冲计时器或以墙钟时间推测网络恢复。

“从头播放”/首集 previous 是明确播放动作，取消已完成/待连播状态，在原会话定位零秒并调用 `setPlaying(true)`；与保持暂停的普通跳转区分。加载时 `rememberPosition` 更新当前位置意图，元数据从该会话最新意图恢复，保留最后暂停/继续操作；新会话初始化自己的续播点，旧元数据按来源身份/生命周期隔离，不把初始闭包值覆盖到新操作上。画质、解析权限和分集/队列顺序继续使用既有模块。

`input/gamepad` 是纯输入解释器，`bindings` 管理语义名称和冲突交换，`geometry` 与 `focus` 负责空间移动、范围约束及相邻焦点恢复。`controls` 调整原生选择框、滑条和长简介；`player-actions` 通过类型化接口处理播放器动作。`use-input` 统一键盘/手柄、窗口失焦与设备切换的中立门控；`hints` 只向活动范围的 `data-input-hints-host` 写入实际按键动作与必要开关状态，后台与隐藏控件不显示提示。播放器上一项/下一项使用 `PlayerControls` 的 `data-player-action` 标记读取当前可访问名称和可操作状态，分别显示映射按键；分集/队列判断仍归属原控件与播放协调，提示不复制业务状态，也不展示直播缺席的重播动作。

`use-input` 根据活动焦点范围决定空格语义：播放器范围走暂停/继续，覆盖层使用原生按钮/开关激活，防止误控背景媒体；手柄语义仍由上层隔离。`ScreenKeyboard` 的选区编辑保存本次目标文字与光标，通过布局阶段与受控值同步提交，外部值变化清除不匹配意图；不依赖下一绘制帧恢复光标，连续删除不读取暂时停留在末尾的位置。

`ScreenKeyboard` 确认拼音候选后经 `scheduleFocusReturn` 在原活动范围恢复最后字母键；后续 Tab、方向、候选翻页或模式操作取消迟到返回。文本和剩余拼音同步提交，不与焦点恢复绑定，普通确认及 Start/Y 分步提交规则保持。

候选与无候选拼写共用 `commitBuffer` 提交本次草稿、剩余拼音和焦点意图，`confirmBuffer` 仅在词库就绪时保留无候选原文；`complete` 在待选拼音为空时才提交上层。空格在有拼音时确认、无拼音时插入空格，表单和手柄遵循相同分步规则。搜索及嵌套文本编辑的必要按钮/提示使用“确认输入”与“搜索/完成”，不把无候选确认绑定到路由切换。

`usePlayerOverlay.reveal` 统一控制层延迟落焦，可接收按优先级排列的目标选择器；默认定位暂停/继续，单集 X 依次定位清晰度、播放速度、播放设置。通过 `scheduleFocusReturn` 核对当前范围及后续输入，新的导航、覆盖层或隐藏操作优先，不把焦点意图绑定到媒体操作；显隐、阅读与自动隐藏继续由原控制层状态管理。

`use-input.act` 在当前语义处理消费动作后立即返回，随后才修复有效焦点并执行长内容滚动或空间导航；跳转预览不再被旧标题/分集信息的滚动拦截。普通阅读先经过播放器的控制层活动更新，未消费的上下键继续按现有规则滚动；B 取消或 A 确认预览后仍使用同一阅读焦点，不改媒体解析、播放顺序或文本内容。

`Player` 的首集从头播放和已完成媒体的明确重播在复位完成/位置/播放意图时同时撤销 `seek` 草稿，避免后续确认提交旧目标；普通暂停/继续不撤销草稿，原确认/取消与播放状态规则保持。`renderer-restart-preview-smoke.mjs` 验证默认/重映射及指针入口，隐藏电影完成脚本使用真实预览和暂停后重播观察原生解码，不替换媒体字节。

`use-browse-focus` 管理切栏与搜索的落焦意图，同页再次提交也产生新的意图。`useBrowseFeed` 核对当前列表与查询缓存的归属，`FeedResults` 用 `data-browse-ready` 明确传递就绪状态，避免路由提交与列表撤换之间先聚焦旧卡片。加载结束优先当前内容，空/失败优先相关筛选/重试；新的有效语义动作、指针操作或覆盖层取消意图，忙碌控件的无效确认保留意图。栏目栏确认和肩键选择保持所属导航入口，肩键新选择同样取消旧搜索落焦。详情辅助按钮用 `data-gamepad-skip` 从手柄焦点候选中移除，切回手柄时修复到所属卡片；键盘 Tab 与鼠标保持入口。播放退出的焦点恢复不等待后台初始化完成。

`FeedRefresh` 统一刷新按钮的等待焦点与重复确认门控，不调度数据。失败请求保留其消息供重试等待时显示，完成成功后撤去；收藏夹读取失败也在成功恢复后清除。`FeedResults` 的重试按钮使用可保留焦点的禁用语义，空列表恢复通过原落焦模块进入当前结果，有内容时保留列表及重试位置。

`focus-return` 在 Modal 打开前记录入口、所属卡片及同列表的相邻项，关闭时在当前活动范围恢复；入口因收藏移除消失时不退回栏目。详情与账号忙碌动作使用 `aria-disabled` 和 `data-focus-retain`，语义确认与业务门控阻止重复操作；收藏选择等待期间保持提交目标。刷新二维码期间保留原刷新按钮，断开账号有独立操作状态。

`CardLayoutSetting` 保存自动或每行 2–6 个卡片；`card-layout.css` 仅覆盖共享网格列数，自动保留原有桌面/电视默认值。播放器固定媒体增益为 1，不呈现音量控件；偏好中的旧 `volume` 字段仅保留兼容读取和写入。

上层状态控制后台 `inert`，嵌套弹窗只允许最上层操作；局部收藏面板用 `data-back-action` 优先收起。关闭弹窗恢复显式入口，播放返回使用媒体与分集的稳定焦点身份。`use-text-entry` 将手柄文本确认转换为缓冲编辑，`TextEntry` 复用 `ScreenKeyboard`，提交与取消明确区分；原生键盘输入保留。

`SearchInput` 同样缓冲关键词，提交时才更新顶层搜索状态。`ScreenKeyboard` 接线中英/数字模式、候选分页、上下文快捷键和待选拼音；`input/pinyin` 索引随包词库，`text-editing` 按选区及字素修改文本，`use-ime-guard` 阻止原生输入法确认时误提交。`hub-input-action` 可由活动键盘取消分发，避免 LB/RB 或 X 同时触发后台操作；快捷提示读取真实映射。AOSP 词库在构建前由固定来源生成，运行时不依赖网络输入服务，来源及许可证随资源分发。

`styles.css` 仅装配按职责拆分的样式模块，共享浅色/深色主题变量；输入焦点与播放器扩展样式继续归属相应模块。新增样式保持正常排版，每个手写文件遵守 300 行限制。前端只呈现任务必要文案，变更说明保留在开发文档。

Liquid Glass 风格由 `styles/tokens.css` 定义中性主题、蓝色强调、清透填充/边缘/低模糊及环境底色；`glass.css` 只将材质应用于导航、搜索和临时操作层，内容卡片/正文不整体模糊。`GlassOptics` 挂载视觉专用 SVG 定义，`visual/glass-optics.ts` 观察有限的玻璃容器及尺寸、维护/清理滤镜，`glass-displacement.ts` 按圆角矩形法线生成中心中性、边缘弯曲的有界位移图。滤镜只折射背后的画面，文字/焦点不变形；大弹窗保留较柔和的背景以分离正文。`glass-player.css` 提供清透播放层和按钮/时间/提示的浅色玻璃衬底配深色文字，底部提示与状态并排、两行容量保留但取消独立状态行，减少空白而不因输入模式移动控件。`glass-accessibility.css` 为减少透明度、提高对比度及强制颜色提供回退，不改变控件几何位置。无背景滤镜能力时使用实色基底，减少动态效果沿用响应样式。CSS/SVG 是对 Apple 材质的光学近似，不调用 Apple 原生渲染引擎。

应用识别图标使用 `public/app-icon.svg` 及同源透明 `app-icon-512.png`，预览 favicon 读取 SVG，原生窗口从开发 public 或发行 dist 读取 PNG；路径基于 `app.getAppPath` 和 join，不依赖开发机目录。electron-builder 的统一 icon 配置转换平台格式，SVG/PNG 随 Vite 进入生产 renderer。`build-app-icon.mjs` 是资源更新时的可选无窗口生成工具，普通构建不调用它；图标读取和 ICO 字节检查不代表真实桌面任务栏或其他系统的 UI 验收。

所有远端分页栏目复用一屏距离预取与 100 毫秒滚动去抖；`browsePagination` 只合并非推荐分页，保持来源顺序和 ID 去重，连续五页无新增或历史/动态游标停滞、回环时停止。失败不推进页码或游标，重试原失败页。弹窗、准备播放、播放与后台页面暂停追加；本机片库、历史和队列一次性读取。

`CollectionChange` 是已成功的平台收藏/稍后再看写入通知，不增加 IPC 能力。`useMediaDetails` 成功后更新局部动作或收起面板，失败不发布成功状态；过期响应不更新已关闭的详情，但确认写入通知仍可使所属账号缓存失效。`useBrowseFeed` 以账号身份/版本约束通知，仅失效具体列表键，移除过滤已知项，添加按来源重新读取而不自行排序。关闭覆盖层或再次访问该栏目时刷新，失败保留列表及失败请求。已确认/已读取的稍后再看状态跨详情保留，完整列表读完时纠正过期成员状态；账号变化清除状态与失效标记。推荐及搜索缓存保持原合同。

`refreshFavorites` 将已加载的收藏页前缀串行重读，以独立非推荐分页合并规则去重并保持来源顺序，最后一次提交全部结果及实际页号。晚页失败不提交部分前缀，重试保留目标深度；实际末页提前结束。每次读取及提交前检查当前请求版本，切换路由/账号后停止并丢弃结果，返回仍可完成所属缓存的失效刷新。

## 数据与凭证边界

`MediaItem` 是长期内容引用，`MediaPart` 是分 P/剧集，`PlaybackSource` 是一次解析的短期媒体会话并携带完整分集列表。`DynamicItem` 保留作者、图文、视频和原始转发动态。历史与队列保存内容引用，不保存 B 站 CDN 链接。任意来源的普通 URL 由用户输入，含用户密码的地址被拒绝。

`bilibili-pgc` 适配影视列表、历史和分集，`shared/bilibiliReference` 仅规范化平台标识：空 BV 号与零值 ID 转为缺省，不进入严格 IPC。`storage/pgc-references` 在读取旧影视历史/队列时兼容这些占位字段，不改变存储版本、身份键或进度。播放参数使用详情返回的有效分集 ID。

`bilibili-pgc-playback` 请求影视 v2 播放接口并展开 `video_info`，校验内部权限错误、试看及加密状态；明确的非加密标志优先于技术类型元数据，过滤加密轨。受保护或旧式多段响应仅通过同一 v2 接口协商 MP4 格式，使用同一账号、分集和请求清晰度，最终画质与试看状态以返回流为准。权限失败不协商格式；仍只有加密流时保留错误，不自动打开浏览器。兼容流继续使用原有 PlaybackSessions、受限媒体网关、分集进度与播放器控制。

片级 `is_drm=true` 且未声明明确保护技术的 DASH 由 `bilibili-pgc-stream` 读取受信 HTTPS CDN 的初始化段，最多 64 KiB、并发 3、超时 10 秒且不跟随重定向，不携带账号凭证。`mp4-protection` 纯解析完整 ISO BMFF 盒与音视频 sample entry，确认没有保护结构才返回 clear；加密、未知/截断结构或读取失败均拒绝。保留片级标记，仅将验证过的轨道交给播放器，不读取密钥、不剥除保护。

`bilibili-search` 并发查询普通视频、番剧、影视和直播间四类搜索接口，按原类别及类内服务端顺序组合，不按响应先后重排；影视映射为 season 引用，不使用媒体资料 ID 替代 season ID。`bilibili-signing` 共享签名键读取与缓存，失效后的迟到读取不覆盖新键，保持原 -403 重试一次规则。综合搜索游标记录页号及仍有后续页的类别，任何类别失败均保留错误。前端按关键词与类型缓存，搜索刷新沿用当前关键词、类型重读首页，也可重试已缓存的空结果。

直播栏目固定为 `followingLive`，删除广场 UI、IPC 类别及接口分支。`bilibili-live` 适配关注和搜索结果的房间身份、数值/字符串状态，优先实际关注接口的 `room_cover`，兼容 `user_cover`、`cover_from_user` 和关键帧；封面继续经过原有无凭证受限图片通道。

`HubApi` 只提供显式操作。渲染器启用 sandbox、contextIsolation，禁用 Node；主进程校验窗口、主 Frame、应用来源和输入形状。任意本地路径不能直接播放，必须对应用户通过文件选择器授权的片库记录。渲染器不接触 Cookie、App access/refresh token。

凭证使用 Electron safeStorage。Windows 使用 DPAPI，macOS 使用 Keychain，Linux 使用系统可用的安全后端；Linux `basic_text` 被拒绝。没有密钥环时只保存到内存。撤销/重新授权递增 generation，旧刷新或扫码请求不能覆盖新凭证。

媒体服务只监听 `127.0.0.1` 随机端口，路径为不可预测的会话 capability，不接受客户端传入文件路径/远端地址。B 站媒体仅附带 Referer，不转发账号 Cookie/Token。HLS 子清单、片段、密钥 URI 都注册同一会话；释放会话时撤销路径并中止请求。字幕、更多 PlayerBackend 或转码未来可以接在 PlaybackSessions 后，前端无需了解账号协议。

视频弹幕仅接受有效播放会话，由会话的真实分集 cid 请求固定 HTTPS `comment.bilibili.com` 端点，不接受渲染器提供 URL/cid、不发送凭证、不跟随重定向；限制 15 秒及 4 MiB，缓存同会话请求，释放时中止读取。只解析普通滚动、反向和固定文本，不处理脚本或高级动画模式。请求失败保留为弹幕状态，不使视频播放失败。

`Store.update` 在串行队列中基于最新已提交状态计算下一版本，临时文件写入并原子重命名成功后才发布到内存，避免设置或队列失败后被其他历史写入重新持久化。配置恢复完成前不覆盖有效初始状态，坏文件保留备份。

## 推荐与恢复

`usePlayerOverlay` 通过播放器的鼠标移动/离开事件记录是否实际停留标题或底部控件，仅将该状态用于暂停自动隐藏；离开、窗口失焦/隐藏或语义/原生键盘输入后清除，显式隐藏也清除。挂载时注册输入与窗口可见性监听，卸载清理；不把鼠标保护与媒体、参数选择或焦点恢复耦合，保留原暂停/阅读/编辑/错误规则。

播放器底部提示由 `styles/player.css` 的网格预留两行按键和独立状态行，行高随桌面/电视字号计算。只覆盖底部提示宿主的布局占位，内部 `.controller-focus-hint` 仍遵守隐藏/活动范围规则；宿主空、鼠标隐藏、短跳转提示或转移到参数菜单时不改变进度条和按钮的位置。浏览提示布局保持；通用覆盖层使用自身 modal 提示占位，不新增隐藏提示或复制操作说明。

App 推荐参照 BewlyCat 实际调用的 pad/iphone、TV App Key、中文地区参数及 Cookie，初始 idx=1，后续使用最后保留卡片的 idx；按原始 aid/bvid 去重并保留顺序。Provider 每次一批，前端串行补足30项并维持一屏预取。刷新先清空；首页/平台页共享 Provider 缓存。动态全部/视频分别缓存，以服务端 offset 分页。没有静默 Web 推荐降级。详见 recommendation-parity.md。

普通视频按视频与 cid、影视按 episode、本地按文件 ID 保存进度。每 5 秒记录一次，暂停、切换、退出时额外保存。跳回前部会写入当前位置，不能简单取历史最大值。B 站回写独立于本机保存，回写失败不会阻止续播。

平台回写由 `history-sync` 在后台串行发送，等待中的同分集更新合并为最新位置，执行前检查账号身份及同步开关；本机落盘完成即可返回，网络请求不阻塞切集或退出播放器。退出应用不等待平台网络回写。续播位置计算由 `shared/playback-progress` 统一，首页与历史标签和现有片尾十秒重播阈值一致。

播放队列由用户显式添加，先连续播放当前视频的全部分集，再进入队列下一项；推荐列表不会自动进入队列。清晰度切换保存并显式传递当前位置，避免接近片尾时触发普通续播的完成阈值。解析期间的返回会取消待播放请求并释放过期会话。当前仅支持一个活跃播放器和一个主要账号组合。

播放错误重试经 `usePlayback` 重新解析同条目/分集/清晰度并显式传递精确位置；切换状态阻止重复/冲突动作，返回保留取消能力。播完状态揭示控制层并聚焦重播。队列忙碌使用 `aria-disabled` 与 `data-focus-retain` 保留入口，语义确认阻止禁用操作；焦点恢复在边界、移除和 DOM 暂时失焦时优先所属/相邻条目的播放控件。

B 站公共图片统一 HTTPS，桌面经 `yingji://app/image` 加载。图片通道仅允许 hdslb.com/biliimg.com 域名，限制格式、体积和跳转，仅附带 Referer 与 User-Agent，不发送账号凭证。

## 扩展约定

`electron/window-fullscreen.ts` 串行处理电视设置与播放器的全屏请求，已有目标直接返回，其余等待原生窗口确认；超时/关闭/异常撤下监听并拒绝请求，后续操作可重试。隐藏隔离模式不设置窗口全屏。IPC `getFullscreen` 只接受空参数，preload 显式暴露读取与布尔 `window:fullscreen` 订阅。`usePlayerWindow` 保存初始化查询取得的实际窗口状态，按钮查询按版本隔离较新事件，卸载撤销监听；初始查询完成前不猜测切换目标，请求等待保焦与控制层显示。退出禁止新请求、等待已发出的操作后恢复进入播放时的实际状态；仅播放期间明确编辑电视偏好时使用最新设置。网页预览使用 DOM 全屏事件，发行桥必须提供能力；类型可选仅为旧桥及夹具兼容。无窗口/单元回归与隐藏状态 IPC 验证不等同于真实 Windows/macOS 全屏动画验收。

`usePlayerMedia` 区分点播的速度状态与当前媒体输出速度；直播在元数据恢复及输出更新时统一使用 1，点播继续使用已有临时选择。切换来源不改写速度状态/存储，队列返回点播恢复临时值，新打开播放器读取默认值，解析与播放顺序保持。无窗口直播回归检查完整操作边界；可选 `player-test-live.mjs` 在既有隐藏账号流程中实际打开正在直播的关注房间，以真实视频帧/媒体时间验证解码和暂停/继续，缺少活动房间时不宣称已实播。

`playerAction` 在处理暂停快捷键前先核对选集范围；选集与参数菜单消费后台暂停、切集、快进和队列动作，不影响实际播放或完成状态。方向/A 留给活动选集控件，X/B 关闭并使用原入口恢复，原生空格仍由输入层保留确认语义。隔离使用动作语义，因此重映射后同样有效；关闭面板后常规暂停动作恢复。`renderer-episode-shortcuts-smoke.mjs` 用无窗口桌面/电视夹具检查上述范围，不代表实体手柄或媒体解码。

`usePlayerCompletion` 按会话一次消费完成事件，媒体由 `Player` 先暂停并保存。自动连播待执行动作与当前会话绑定；设置/队列、选集/参数菜单或跳转预览活动时保留界面和焦点，结束编辑后调用既有切换协调，不自行计算播放顺序。失败来源恢复通过显式 canResume 检查完成状态，避免已播完原视频从头播放。主动切换、错误、休眠或退出取消等待，重播/回退进度解除同会话完成锁；关闭再开启自动连播不追溯旧事件。`EpisodePicker` 接受完成状态，当前集确认可从头重播。`renderer-completion-smoke.mjs` 检查编辑隔离、去重、取消、恢复与桌面/电视布局，媒体及手柄为夹具。`player-test-completion.mjs` 在隐藏账号电影中定位片尾并等待原生结束，验证编辑期间无解析、菜单/焦点保持及真实重播，不模拟 ended，不代表观看全片。

进度条切换等待使用 `aria-disabled` 和 `data-focus-retain` 保留入口，`Player` 在预览/提交前核对切换与错误状态，原生输入事件也经过业务门控；不依靠手柄映射单独拦截。输入提示对等待中的 range 只显示上下移动，常规控制层隐藏样式只作用于其内部提示；错误页/菜单保留活动提示与指针。`renderer-seek-transition-smoke.mjs` 使用隔离媒体和请求检查指针/原生键盘/手柄、成功/失败恢复与精确位置，不代表真实媒体解码。

`PlayerTimeline` 分离原生滑条呈现和指针草稿生命周期，原生滑条自身处理拖动，控件与窗口的释放/取消共用同一 pointerId 归属检查；只接受在进度条开始的手势，不因其他区域起始的松开、无关指针或旧手势提交/撤销键盘及手柄预览，卸载清除监听。确认前不修改媒体，控件移出/取消清除草稿以拒绝迟到释放。窗口失焦/隐藏只撤销正在进行的指针拖动；没有指针手势的键盘/手柄预览保留显式确认/取消语义。已取消的原生手势通过本模块的中断标记拒绝后续 input/释放；指针新按下或原生范围编辑键开始新操作，外部 B 撤销也中断原手势。进度百分比只作为样式变量传给 `styles/player-timeline.css`，3px轨道与12px圆点保留24px原生点击高度；键盘/手柄焦点仅描边圆点，避免全宽胶囊框。实际提交仍由 `Player.commitSeek` 核对播放切换并记录位置。隐藏时 Down 优先可用进度条，Up 使用播放按钮，左右预览优先进度条；继续复用 `reveal` 和取消过时落焦的既有规则，直播/未就绪安全回退。

`shared/playback-next` 用纯数据返回 episode/queue/unknown 或无目标，保留已有当前分集优先、再进入当前条目后的队列项、不循环/不选队首规则。`usePlayback.next` 与只读 `nextKind` 共用目标函数，未知分集经原详情接口解析且核对播放代次；App 将能力接线到 Player，PlayerControls 依能力禁用无目标按钮或呈现准确名称，提示继续读取当前按钮。Player 的快捷键/播完推进仅在有目标或未知可解析时提交原 transition，不为无目标暂停、保存或解析；不改变媒体会话与播放顺序。

未知分集详情成功后，`usePlayback` 在代次/会话核对后补全当前 `PlaybackSource.parts`，让下一项、上一集和选集共同使用已确认的列表。媒体效果按 sessionId 管理，补全元数据不重建引擎、复位位置或改变暂停/倍速。`shared/playback-parts` 仅在新解析未提供列表、来源和条目一致且新当前分集属于旧列表时继承；显式平台列表（包括空列表）优先，不继承其他媒体字段或权限，不跨条目、退出或取消边界保存。

`PlayerControls` 的上一项/可解析下一项等待以 aria-disabled 和 data-focus-retain 呈现，沿用空间焦点保留规则；方向仍可移动，确认在播放器语义层和实际动作层门控，提示省略无效确认。原控件保持存活和焦点，不排队恢复、不覆盖用户后来移动；来源成功仍沿原准备流程落焦，失败保留原播放意图。没有后续内容的下一项使用原生 disabled，继续跳过空间导航，与暂时等待明确区分。

隐藏账号电影的 `player-test-preview-ownership` 通过现有UI暂停、键盘预览/确认和模拟指针检查真实媒体位置，独立于平台解析和推荐；返回明确标记模拟指针及实际进度/暂停/倍速。上层账号脚本在运行前覆盖报告，失败标记与清理结果也写入当前报告，仍以本次退出码判断整轮通过，不读取旧成功报告推断当前结果。

`PlayerFeedback` 通过可选回调呈现错误页清晰度入口，只有服务端提供选项时显示；菜单复用 `PlayerOptionPicker`，由父层将错误控件 inert，取消恢复入口。`Player` 确认后沿既有串行切换通道按原位置重新解析，当前清晰度亦可重试；新会话明确恢复播放，不继承故障暂停，正常暂停中的切画质规则保持。错误页收起常规控制层，解析失败仍保留恢复入口，返回取消迟到结果。

`node scripts/renderer-error-quality-smoke.mjs` 无窗口检查错误页画质恢复、菜单范围/焦点、同值重试、等待/失败/返回和无选项来源；桌面及产品开关启用的电视模式均检查命中与截图。电影脚本在模拟故障后分别验证真实 1080P 重试和 720P 恢复，记录原生精确定位，不替换媒体响应。

隔离实播同时设置 `YINGJI_TEST_DATA` 与 `YINGJI_TEST_HIDDEN=1` 时，主进程创建隐藏、静音且跳过任务栏的窗口，阻止全屏、第二实例抢焦点及启动错误弹窗。正常启动保持原行为。`movie-account-hidden.mjs` 使用明确授权的加密副本与关闭历史回写的测试配置核验实播、窗口状态及清理；可对独立打包目录运行，不覆盖或重启日常应用。

新来源应实现列表、详情、临时播放解析，再按能力增加收藏/历史操作；不要把 API 请求直接写进 React 组件。新持久字段需升级存储 version，并保留迁移与备份逻辑。新桌面能力必须同时更新 shared/types、ipc schema 和 preload 白名单。

跨平台代码使用 Node path、Electron userData、OS safeStorage 和 Chromium Gamepad，不写死磁盘盘符、不调用 shell、不依赖 XInput 专用原生库。打包需分别在目标 OS 验证；此架构不等于 OpenWrt/N1 客户端。



手机收藏/队列由companion-library解析会话句柄后调用既有写入通道，collectionChanged只失效发起账号的相应缓存。tv-login只打开电视既有扫码界面，不向手机返回扫码图像/ID/平台凭证。RemoteApp仅固定顶栏，播放状态自动进入控制页，返回首页收成气泡，其余操作以PhoneSheet打开。清晰度依据见 [调研说明](bilibili-quality.md)。
