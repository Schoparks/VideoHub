# B 站清晰度：分辨率、码率与帧率

2026-10-25 调研与实现说明。

## 依据与边界

B 站官方[清晰度升级说明](https://www.bilibili.com/blackboard/activity-quality2pc.html)将1080P+描述为码率增强，将1080P60描述为帧率增强。两者是不同维度，不能因为qn112小于116就认为前者必然低于后者。该页面是历史升级说明，其中码率数字不作为当前所有视频的固定规格。

当日匿名读取两个公开视频的官方 `x/player/playurl`：

- [BV1ze4y1Q7ym](https://www.bilibili.com/video/BV1ze4y1Q7ym/) 的格式声明含116、80、64、32、16，没有112。
- [BV1uk4y1F7yM](https://www.bilibili.com/video/BV1uk4y1F7yM/) 的格式声明含127、120、80、64、32、16，没有112或116。
- 两次匿名返回的实际DASH轨道均只有32、16。格式声明不等于该账号可播放档位，不能把声明直接做成可切换菜单。

这些样本未出现高码率与60帧同时提供，但不足以证明平台对所有视频保证互斥。代码不写死互斥，也不补造缺少的档位。调研未使用日常账号、Cookie或会员凭据，未下载视频；有限记录在 `.tmp/quality-research.json`。

## 行为

- 设置上限仅呈现不限、4K、1080P、720P、480P、360P、240P。1080P包含80/112/116，720P包含64/74；旧上限112/116迁移为80，74迁移为64，其他偏好及具体记忆档位不重置。
- 菜单保留实际可播放档位的独立身份；80显示“1080P”，不加“普通”。不根据`accept_quality`或`support_formats`单独虚构权限。
- 自动选择先比较分辨率，同分辨率沿服务端实际轨道顺序选择，不按qn数值推断高码率与高帧率的优劣。请求阶段的qn仅用于平台协商，最终候选仍由实际轨道和编码能力决定。
- 记忆或手动指定档位存在时优先精确匹配；缺档时先在不高于目标分辨率的候选中取最高分辨率，同分辨率保留来源顺序。只有更高分辨率时取上限内最低可用分辨率；没有合格候选则失败。回退不覆盖记忆。
- 保留既有限制模式对HDR/杜比档位的排除，它们的名称本身不指定像素上限；不限模式仍使用实际可播放格式。本轮不改变权限、编码能力、直播和其他来源。

单元测试分别构造只提供112、只提供116、同时提供及缺失的情况，用于防止写死关系，不把这些夹具声称为真实平台组合。
